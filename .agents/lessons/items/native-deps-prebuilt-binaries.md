### Native deps on Windows need N-API prebuilds; host ABI is not Electron ABI

**Lesson:** Prefer dependency versions that ship **N-API** prebuilds for every target runtime, not just the host Node ABI. For code that runs inside Electron, verify the module loads in a real Electron process — a prebuild matching host Node can still fail there (NODE_MODULE_VERSION differs: host Node 24.18 = 137, Electron 44 = 149). Keep `pnpm-workspace.yaml` `allowBuilds` as the standing gate: `true` only for reviewed packages with required install scripts (node-pty staging, esbuild, biome), explicit `false` for packages whose implicit `node-gyp rebuild` must never run (better-sqlite3 13.x ships `prebuilds/*.node`). In packaging, set `npmRebuild: false` (electron-builder.yml) when all natives are N-API.

**Reason:** This host has no Visual Studio C++ Build Tools, so `node-gyp rebuild` always fails. better-sqlite3 12.x (V8 ABI) passed tests under host Node but crashed Electron main at startup; 13.x (N-API, bundled prebuilds incl. win32-x64) works in host Node, Electron main, and the packaged/installed app (verified 2026-09-24). The old advice "better-sqlite3 >= 12 is enough" was wrong for Electron — superseded here.
